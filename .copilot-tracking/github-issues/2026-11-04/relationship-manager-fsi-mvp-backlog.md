# relationship-manager-fsi MVP 백로그 계획

> 인간 검토용 초안입니다. 이 백로그는 경영관리 분석 에이전트의 첫 실현 가능한 MVP를 의도적으로 좁게 정의하며, 세션 연구, PRD, 경험 초안을 기준으로 합니다. 이는 계획 아티팩트일 뿐이며 실제 구현이나 게시를 수행하지 않습니다.

## 1. 목표와 제품 프레임

첫 번째 MVP는 관리자가 승인된 운영 근거를 검토하고, 예외를 요약하며, 인간이 조치를 취하기 전에 사실과 가정을 분리할 수 있도록 지원하는 고신뢰, 좁은 범위의 도우미를 제공합니다. 핵심 가치는 자율적 의사결정이 아니라, 더 빠르고 안전하며 설명 가능한 의사결정 지원입니다.

## 3. MVP 성공 정의

MVP는 다음 조건을 충족할 때 성공한 것으로 간주합니다.

- 승인된 근거만으로 경영 질문을 제기할 수 있다
- 사실, 가정, 불확실성이 명확히 분리된 구조화된 요약을 받을 수 있다
- 관련 소스 데이터와 정책 제약을 식별할 수 있다
- 해결되지 않거나 위험한 사례를 인간 검토자로 에스컬레이션할 수 있다
- 검토 없이 지원되지 않거나 무단인 조치를 방지할 수 있다

## 4. 백로그 구조

### 에픽 E1: 근거 기반 경영 인사이트

목표: 승인되지 않았거나 약하게 지원되는 정보를 노출하지 않으면서, 경영 질문을 안전하고 근거 기반으로 지원하는 워크플로우를 제공한다.

#### 기능 F1: 범위 및 신뢰 게이트

우선순위: P0

- 스토리 S1-1: 세션이 승인된 근거 경계와 허용 가능한 데이터 소스를 정의하도록 보장
  - 작업:
    - 소스 루트와 승인된 파일 목록 확인
    - 데이터를 확인된 사실, 추론 패턴, 가정, 미확인으로 분류
    - 처리 전에 미승인 입력을 거부하거나 표시
- 스토리 S1-2: 데이터 검색 전 권한 및 민감도 검사 적용
  - 작업:
    - 사용자 역할과 접근 범위 검증
    - 무단 또는 민감 데이터 접근 차단
    - 데이터가 없거나 제한된 경우 명확한 메시지 표시

#### 기능 F2: 경영 질문 수집 및 소스 선택

우선순위: P0

- 스토리 S2-1: 비즈니스 질문을 받아 관련 승인된 소스에 매핑
  - 작업:
    - 지원 질문 유형 정의
    - 관련 CSV 또는 데이터 테이블 식별
    - 누락된 데이터나 지원되지 않는 쿼리 강조
- 스토리 S2-2: 경영 검토용 짧은 의사결정 지원 흐름 지원
  - 작업:
    - 의사결정 맥락과 긴급도 수집
    - 시간 범위와 KPI 또는 지표 집합 식별
    - 제약 또는 특수 가정 공개

### 에픽 E2: 구조화된 요약 생성

목표: 경영진이 빠르게 읽고 검토할 수 있는 짧고 이해하기 쉬운 형식으로 결과를 제시한다.

#### 기능 F3: 요약 및 예외 합성

우선순위: P0

- 스토리 S3-1: 사실, 신호, 이상 지점을 포함한 짧은 요약 생성
  - 작업:
    - 주요 추세와 이상치 요약
    - 기대와 다른 성과 지점 식별
    - 소스 참조 또는 테이블 이름 포함
- 스토리 S3-2: 출력에서 가정과 근거를 분리
  - 작업:
    - 사실 목록과 가정 목록을 별도로 표시
    - 불확실성과 미해결 질문을 명시적으로 드러냄
    - 지원되지 않는 결론에 대해 확신 있는 표현을 방지

#### 기능 F4: 인간 검토 가이드 및 에스컬레이션

우선순위: P0

- 스토리 S4-1: 후속 조치와 검토 트리거 강조
  - 작업:
    - 임원 검토가 필요한 이슈 식별
    - 후속 점검 또는 데이터 검증 단계 제안
    - 조치 전 명시적 인간 승인 요구
- 스토리 S4-2: 고위험 사례를 위한 구조화된 에스컬레이션 경로 제공
  - 작업:
    - 정책, 위험, 거버넌스 민감 항목 플래그 지정
    - 맥락과 근거를 갖고 인간 검토자로 경로 전달
    - 근거가 부족할 때 흐름 중단

### 에픽 E3: 신뢰, 사용성, 품질 검증

목표: 경영 환경에서 사용 가능하고 이해 가능하며 안전한 경험인지 검증한다.

#### 기능 F5: 품질 검사 및 사용성 검증

우선순위: P1

- 스토리 S5-1: 요약 가독성과 경영진 사용성을 검증
  - 작업:
    - 응답 지연과 명확성 테스트
    - 의사결정자가 빠르게 읽을 수 있는지 확인
    - 요약이 스캔 가능하고 구조화되어 있는지 확인
- 스토리 S5-2: 실패 사례와 거버넌스 통제를 검증
  - 작업:
    - 약한 근거, 기밀 데이터 요청, 누락된 컨텍스트 시뮬레이션
    - 시스템이 적절히 거부하거나 에스컬레이션하는지 확인
    - 지원되지 않는 결론이 불확실로 표시되는지 점검

#### 기능 F6: 보고 및 운영 인사이트 메트릭

우선순위: P1

- 스토리 S6-1: 사용량과 결과 메트릭 수집
  - 작업:
    - 보고서 준비 시간 절감 측정
    - 신뢰도와 검토 수용률 추적
    - 에스컬레이션 및 미해결 사례 수 기록
- 스토리 S6-2: MVP 검증을 위한 성공 임계값 정의
  - 작업:
    - 검토 시간 및 요약 품질의 KPI 기준 설정
    - 사용 전후 사용자 신뢰도 비교
    - 근거 커버리지를 이해관계자 기대치와 연결

### 에픽 E4: Marketplace 준비 상태 평가

목표: 게시 주장 없이 Marketplace 또는 Microsoft 365 Copilot Agent Store 준비성을 평가한다.

#### 기능 F7: 릴리스 게이트 준비 상태 검토

우선순위: P2

- 스토리 S7-1: 법적, 규정 준수, 파트너 준비 상태 평가
  - 작업:
    - 최신 Microsoft 가이드와 정책 요구사항 확인
    - 테넌트 및 파트너별 배포 제약 검토
    - 준비 상태를 승인된 상태가 아니라 잠정 상태로 문서화
- 스토리 S7-2: 릴리스 전제조건 및 차단 요소 정의
  - 작업:
    - 거버넌스, 개인정보, 테넌트 호환성을 위한 필수 통제 목록 작성
    - 승인에 필요한 누락 근거 식별
    - 잠정적인 준비 상태 매트릭스 유지

## 5. 우선순위 라벨

백로그 분류에는 다음 라벨을 사용합니다.

- P0: 첫 데모 또는 MVP 검증에 반드시 필요한 항목
- P1: 신뢰, 사용성, 품질에 중요하지만 P0 범위를 따라갈 수 있는 항목
- P2: 전략적 또는 출시 준비 관련 항목; MVP 핵심이 검증된 뒤 평가

## 7. MVP 슬라이스 수용 기준

MVP 슬라이스는 다음 조건을 충족할 때 완료됩니다.

- 사용자가 승인된 근거만으로 경영 질문을 제출할 수 있다
- 시스템이 관련 소스를 식별하고 무단 데이터 접근을 차단한다
- 출력이 사실, 추론, 가정, 불확실성을 명확히 분리한다
- 출력에 근거 참조 또는 소스 이름이 포함된다
- 인간 검토자는 운영적 조치 전에 반드시 확인해야 한다
- 사용자가 숨겨진 가정 없이 짧은 검토 주기 안에 브리프를 이해할 수 있다

## 8. 위험과 완화 방안

### 위험: 과도한 자동화와 낮은 신뢰

완화: 인간 검토와 명시적 불확실성 레이블을 모든 출력에 요구한다.

### 위험: 무단 데이터 노출

완화: 근거 경계 검사 적용 및 승인된 소스로 Retrieval을 제한한다.

### 위험: 낮은 비즈니스 활용성

완화: 몇 가지 고가치 경영 질문에 집중하고 실제 검토 워크플로우로 요약 형식을 검증한다.

### 위험: 조기 Marketplace 준비 상태 주장

완화: Microsoft 가이드, Partner Center 요구사항, 테넌트별 타당성이 검증될 때까지 준비 상태를 잠정적으로 유지한다.

## 9. Marketplace 준비 상태 평가

첫 번째 MVP는 공개된 Marketplace 또는 Microsoft 365 Copilot Agent Store 오퍼로 간주될 준비가 되지 않았습니다. 워크숍 수준 프로토타입이자 신뢰할 수 있는 MVP 후보로는 적합하지만, 게시 주장을 유효하게 만들기 전까지는 다음 항목이 남아 있습니다.

- 에이전트 또는 솔루션 게시에 대한 최신 Microsoft 가이드가 확인되지 않음
- Partner Center 요구사항과 테넌트별 배포 제약이 아직 검증되지 않음

- governance, privacy, and security controls require explicit review before any live deployment
- actual marketplace packaging and listing requirements are outside the current artifact scope

Therefore, the appropriate status is: provisional readiness for concept validation, not final publication readiness.

## 10. Recommended next step

Proceed with only the P0 slice first: evidence-boundary control, source-aware question intake, structured summary generation, and human escalation. Validate that flow before moving into deeper platform, compliance, or marketplace work.

This keeps the effort aligned with the repository evidence, lowers implementation risk, and preserves the trust model required by the workshop scenario.
